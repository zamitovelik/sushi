# Mr. Sushi — сайт с доставкой

Сайт-витрина с рабочим каталогом, корзиной и оформлением заказа для
[@mrsushi.uz](https://www.instagram.com/mrsushi.uz/) (Чирчик, Амир Темур 120).

## Запуск

```bash
npm install
cp .env.example .env
npm run db:migrate
npm run dev
```

Откроется на http://localhost:3000.

## Стек

Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · Prisma + SQLite ·
zod · Framer Motion.

Шрифты: Unbounded (заголовки), Golos Text (текст), JetBrains Mono (цены).

## Архитектура

**Меню — в коде** (`lib/data/menu.ts`), а не в базе. Это статический контент
с типизированными переводами на два языка; в БД он превратился бы в JSON-колонки
с потерей типобезопасности. Если заведению понадобится редактировать меню без
разработчика — тогда и переносить, вместе с админкой.

**В базе только изменяемое:** пользователи, сессии, заказы, брони и остатки
на кухне (`prisma/schema.prisma`).

**Цены считаются в одном месте** — `lib/pricing.ts`, общий модуль для клиента
и сервера. При оформлении заказа сервер игнорирует присланные клиентом цены
и пересчитывает сумму сам по своему меню.

**Валидация — в одном месте:** `lib/validation.ts` на zod, схемы общие для
API-роутов и форм.

**Списание остатков атомарное.** `UPDATE ... WHERE quantity >= qty` внутри
транзакции: два параллельных заказа на последнюю порцию не пройдут оба.

## Язык

Переключатель RU/UZ в шапке, выбор сохраняется в `localStorage`. Тексты
интерфейса — `lib/i18n.ts`, названия и описания блюд — `lib/data/menu.ts`.

## Каталог

Фильтрация выполняется на сервере (`GET /api/menu`), клиент только собирает
параметры и дебаунсит запрос:

| Параметр    | Значение                                                            |
| ----------- | ------------------------------------------------------------------- |
| `category`  | `sets` · `rolls` · `baked` · `sushi` · `wok` · `starters` · `drinks` |
| `q`         | поиск по названию и составу, сразу по обоим языкам                   |
| `min`/`max` | диапазон цены                                                        |
| `inStock`   | `1` — только то, что есть на кухне                                   |
| `spicy` / `veg` | острое / без рыбы                                               |
| `sort`      | `popular` · `price-asc` · `price-desc` · `rating`                    |

Позиции с нулевым остатком уезжают в конец списка и помечаются
«Нет в наличии».

## Заказы

Промокоды: `PANDA10` (−10% от 100 000), `CHIRCHIQ15` (−15% от 200 000),
`INSTA20` (−20% от 300 000). Доставка 15 000 сум, от 150 000 — бесплатно.

Принятый заказ уходит в Telegram-бот администратора. Если `TELEGRAM_BOT_TOKEN`
или `TELEGRAM_CHAT_ID` не заданы — заказ всё равно сохраняется, в лог пишется
предупреждение. Отправка не блокирует ответ гостю: падение Telegram не должно
ронять оформление.

## Аккаунты

Регистрация и вход на httpOnly-сессиях со сроком 30 дней; протухшие сессии
удаляются при обращении и раз в час пачкой. Пароли солятся и хешируются
асинхронным `scrypt` — синхронный вариант блокировал бы event loop на всё
время вычисления.

Бонусы: 10 000 за регистрацию, +3% с каждого заказа.

## Что важно знать перед деплоем

- **Лимиты частоты живут в памяти процесса.** При запуске в несколько воркеров
  (PM2 cluster, несколько контейнеров) фактический лимит умножается на их число.
  Для одного инстанса достаточно; для горизонтального масштабирования нужен Redis.
- **`clientIp()` доверяет заголовку `x-forwarded-for`.** Это верно только за
  обратным прокси. При прямом выставлении в интернет заголовок подделывается
  и лимит обходится.
- **SQLite не переживёт нескольких инстансов с записью.** Для горизонтального
  масштабирования — Postgres: меняется одна строка в `schema.prisma`,
  код репозитория не трогается.
- **Фотографий блюд нет.** Каждая позиция получает процедурную SVG-иллюстрацию
  (`components/food-art.tsx`). Когда появятся снимки, `FoodArt` меняется на
  `next/image` в двух местах — в карточке товара и в строке корзины.
- **Оплата не подключена.** Способ оплаты передаётся в заказ как поле,
  реального списания нет.
- Логотип — векторная интерпретация оригинала, а не исходный файл заведения.
